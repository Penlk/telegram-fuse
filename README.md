# FUSE: telegram-fuse

Краткое описание
- Проект: реализация файловой системы на основе FUSE, использующая Telegram как бэкенд для хранения файлов.
- Цель: показать умение работать с FUSE и внешними API, обеспечить монтирование удалённого хранилища как локальной ФС.

Ключевая идея реализации
- Каждый файл сохраняется как сообщение с вложением в указанном чате Telegram.
- При записи файла создаётся новое сообщение с файлом; если файл с таким именем уже существует, новый файл загружается, и только после успешной записи старое сообщение удаляется.
- «Директории» реализованы через теги (labels) в описании сообщения: при перемещении файла в директорию к сообщению добавляется тег с названием директории; при листинге директории показываются файлы с соответствующим тегом.
- Для Telegram: корневая директория — указанный чат; создание директории создаёт отдельный чат/канал (ограничение платформы и API может требовать ручной настройки).
- Временные метки ctime/mtime берутся из даты сообщения с файлом.
- Не реализованы вложенные директории, смена владельца, создание ссылок (symlink) — по ТЗ это необязательно.

Что реализовано (функционал)
- Чтение и запись файлов через FUSE (read, write, open, release).
- Создание/удаление файлов и директорий (директории как теги/каналы).
- Листинг директорий (возвращает файлы, соответствующие тегу/чату).
- Удаление директории — удаление всех сообщений с соответствующим тегом (или удаление канала для Discord-подхода).

Структура репозитория (важные файлы)
- [CMakeLists.txt](CMakeLists.txt) — корневой CMake-файл сборки
- [bin/main.cpp](bin/main.cpp) — точка входа и парсер опций
- [lib/operations/filesystem.cpp](lib/operations/filesystem.cpp) — реализация операций FUSE
- [lib/telegram/file.cpp](lib/telegram/file.cpp) — код взаимодействия с Telegram API (загрузка/удаление/листинг)
- [run.bash](run.bash) — вспомогательный скрипт для запуска (если есть)

Зависимости
- libfuse3 (пакет: `fuse3`, `libfuse3-dev`)
- CMake (>=3.10)
- Компилятор: gcc/g++ или clang
- Библиотеки для HTTP/REST (в проекте используется `cpr` через CMake deps)
- Учетные данные Telegram: бот-токен и ID чата/канала

Сборка
1. Установите системные зависимости (на Debian/Ubuntu):

```bash
sudo apt update
sudo apt install -y build-essential cmake libfuse3-dev libcurl4-openssl-dev pkg-config
```

2. Соберите проект:

```bash
mkdir -p build && cd build
cmake ..
cmake --build . -- -j$(nproc)
```

3. В корне репозитория собранный бинарник окажется в `bin/` или `build/bin/` в зависимости от конфигурации.

Запуск
- Перед запуском задайте переменные окружения с доступом к Telegram API (пример):

```bash
export BOT_TOKEN="<ваш_токен>"
export CHAT_ID="<id_чата_или_канала>"
```

- Монтирование ФС (пример):

```bash
mkdir -p /tmp/tg-mount
./bin/telegram-fuse /tmp/tg-mount
# или, если бинарник в build/bin:
# ./build/bin/telegram-fuse /tmp/tg-mount
```

- Работа с файлами: `ls`, `cat`, `rm`, `mkdir`, `rmdir`, `mv` и др. — изменения синхронизируются с Telegram через API.

Примеры использования
- Создать файл:

```bash
echo "hello" > /tmp/tg-mount/hello.txt
```

- Прочитать файл:

```bash
cat /tmp/tg-mount/hello.txt
```

- Переместить файл в директорию (директории реализованы как теги):

```bash
mkdir /tmp/tg-mount/mydir
mv /tmp/tg-mount/hello.txt /tmp/tg-mount/mydir/
```

Тестирование и стабильность
- Во время разработки проверялись основные команды: `ls`, `cat`, `rm`, `rmdir`, `mv`, `echo > file` — ФС не должна падать.
- Рекомендую тестировать с небольшими файлами и мониторить логи бота в Telegram для выявления ошибок API/лимитов.

Ограничения и известные моменты
- Нет вложенных директорий (по ТЗ).
- Нет поддержки прав/владельцев и символьных ссылок.
- Задержки зависят от сети и скорости Telegram API; при больших файлах/частых операциях возможны задержки.
- Для надёжности при перезаписи выполняется схема: создать новое сообщение → убедиться в успешной загрузке → удалить старое сообщение.

Дизайн решений и причины
- Хранение файлов как сообщений упрощает синхронизацию с Telegram и даёт естественные мета-данные (ctime/mtime).
- Теги в описании сообщения используются для реализации «директорий» без создания вложенной структуры файловой системы на стороне Telegram.
- Для коммуникации с HTTP API использована библиотека `cpr` (подключена через CMake), чтобы не писать собственный HTTP-клиент.
